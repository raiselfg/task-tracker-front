# Рядом — личные и семейные задачи

Локальный фронтенд первой версии PWA. React 19, TypeScript, Vite 7,
React Router 7, TanStack Query 5, ofetch, React Hook Form + Zod,
Tailwind CSS 4, компоненты shadcn/ui на Radix UI и vite-plugin-pwa.
Точные установленные версии закреплены в `bun.lock`.

Формы входа, регистрации, задач и групп используют `useForm` и `zodResolver`.
Поля и состояние изменений формы ведёт RHF; ограничения Zod соответствуют
схемам бэкенда. Оформление компонентов задано utility-классами Tailwind;
в `src/index.css` оставлены только тема и общие базовые стили.
Запросы выполняются экземплярами `ofetch.create`: библиотека сериализует
JSON, разбирает ответы и возвращает `FetchError`. Повторы на уровне транспорта
отключены; запросами сервера и их повторным получением управляет TanStack Query.

## Структура и компоненты

За основу организации кода и оформления взят
[usta/apps/admin](https://github.com/raiselfg/usta/tree/6c115f3cfa4024163bfe6f4bd6161fee007ff058/apps/admin).
Используются модули предметной области, тонкие страницы, фабрики `queryOptions`,
общие UI-компоненты и нейтральные цветовые токены Tailwind.

```text
src/
  routes/                 страницы и сборка экранов
  tasks/
    components/           список, фильтры, статистика, форма, карточка, действия
    lib/                  API задач, типы, Zod, обновление кэша
  groups/
    components/           создание группы, участники, приглашение, действия
    lib/                  API групп, типы, Zod, обновление кэша
  auth/
    components/           форма входа и регистрации
    lib/                  API авторизации, типы и схема Zod
  shared/
    components/ui/        Button, Input, Field, Card, Badge, Dialog
    components/           навигация, заголовки, состояния запросов, PWA
    hooks/                общие хуки
    lib/                  ofetch, QueryClient, queryOptions, общие утилиты
```

Компоненты используют настроенный алиас `@/`. Формы и кнопки действий владеют
собственными мутациями. Поля задачи разделены на содержание, назначение и статус;
`useFormState` и `useWatch` подписывают соответствующие блоки на нужные поля.
Снимок исходной задачи по-прежнему обеспечивает минимальный PATCH.

Статистика запрашивается только на общем экране задач и считается одним проходом.
Имена участников объединяются стабильной функцией `combine` в `useQueries`.
Обновление списка инвалидирует активные запросы задач вместо повторного
`refetch` одного и того же запроса из списка и обзора. Реального замера FPS
или времени рендера не проводилось.

React Router, RHF + Zod, ofetch и существующие зависимости сохранены.
`.prettierrc.json` задаёт одинарные кавычки, в том числе в JSX.

## Запуск

Нужны Bun и Node.js 22.12+. Рекомендуется актуальная LTS-версия Node.js.

```bash
cd /home/sergey/proj/task-tracker-frontend
bun install --frozen-lockfile
cp .env.example .env.local
bun run dev
```

Открыть **http://localhost:3000**. В `.env.local` задайте полный адрес API:

```dotenv
VITE_API_URL=http://localhost:8000/api/v1
```

Префикс `/api/v1` входит в значение переменной. Завершающий `/` допустим.
Браузер обращается к этому адресу напрямую; прокси в dev и preview отсутствует.
Без корректного абсолютного HTTP(S) URL запуск dev-сервера и сборка завершатся
понятной ошибкой. После изменения env перезапустите dev-сервер.

Бэкенд запускается отдельно из `/home/sergey/proj/task-tracker` по его README.
Для локального HTTP нужны `APP_ENV=development`, `ALLOW_INSECURE_COOKIES=true`
и соответствующий origin `http://localhost:3000` в `ALLOWED_ORIGINS`.
Используйте одинаковое имя хоста для фронтенда и API: `localhost` для обоих
или `127.0.0.1` для обоих, с соответствующим origin в CORS.
Код, настройки и бизнес-правила бэкенда этот фронтенд не меняет.

```bash
bun run typecheck
bun run lint
bun run test
bun run build
bun run preview
```

`preview` обслуживает готовую production-сборку на порту 3000. Адрес API уже
встроен в неё при сборке; env запущенного preview его не меняет.
Остановите dev-сервер перед запуском preview.
Service worker работает в production-сборке; для проверки PWA используйте preview.
Если после preview браузер показывает сохранённую production-версию вместо dev,
удалите service worker этого localhost origin в DevTools → Application →
Service Workers → Unregister и перезагрузите страницу.

## Возможности

- Регистрация, отдельный вход, проверка текущей сессии через `/auth/me`, выход.
  Используется только HttpOnly cookie с `credentials: "include"`.
  Приватные запросы и кэш сбрасываются при смене аккаунта, выходе и ответе 401.
  Токены, пароли и приватные данные не сохраняются в localStorage или IndexedDB.
- Задачи: все, личные и конкретная группа; фильтры статуса и исполнителя,
  включая неназначенные задачи. Сервер получает только `group_id`, `status`,
  `assignee_id`. Личные и неназначенные задачи отбираются на клиенте.
- Создание, просмотр, частичное редактирование, смена статуса, назначение,
  выполнение и удаление незавершённых задач. Очистка описания и назначения
  отправляет `null`. PATCH содержит только поля, изменённые в форме.
- Выполненная задача доступна только для просмотра, в том числе при прямом
  открытии адреса редактирования. После конфликта 409 состояние запрашивается
  заново; устаревшая форма сменяется просмотром выполненной задачи.
- Группы: создание, список, задачи и участники; владелец исключает участников
  и удаляет группу, обычный участник может выйти. Перед удалением явно
  перечислены последствия, включая удаление выполненных задач и приглашения.
- Приглашения: создание/замена только по действию владельца, копирование,
  отзыв, просмотр, отдельное подтверждение вступления. Токен создания хранится
  только в памяти открытой страницы. После ухода со страницы исходную ссылку
  восстановить через текущий API нельзя; можно создать новую или отозвать текущую.
- `/invite/:token` сохраняется при переходах между входом и регистрацией.
  После входа открывается просмотр приглашения; вступление не происходит автоматически.
- Русский интерфейс, нижняя навигация на телефоне, боковая на компьютере,
  подписи полей, клавиатурный фокус, диалоги с управлением фокусом,
  состояния загрузки, ошибки и пустых списков.

## PWA и сеть

Манифест, PNG-иконки 192/512, maskable-иконка и apple-touch-icon находятся
в `public/`. В поддерживаемом браузере доступна установка; для остальных
кнопка установки объясняет действия в меню браузера.

Service worker предварительно кэширует только файлы интерфейса.
`/api` исключён из навигационного fallback. Runtime-кэширование запросов
не настроено: запросы к API проходят напрямую в сеть, в том числе на другом origin.
HTTP-клиент также задаёт `cache: "no-store"`. Авторизация и ответы API
не попадают в Cache Storage. Пользовательские данные после перезагрузки
без сети недоступны. Открытая форма остаётся в памяти вкладки при потере
соединения; экран сети скрывается автоматически после подключения.

Записи не ставятся в офлайн-очередь: мутации имеют `networkMode: "always"`,
отключённые повторы и проверяют наличие сети перед запросом. После ошибки
пользователь повторяет действие сам. Изменения других участников подгружаются
при возвращении в окно и вручную кнопкой обновления; realtime-подписки не предусмотрены.

Обновление service worker предлагается кнопкой. Автоматического `skipWaiting`
и принудительной перезагрузки нет. Если в форме есть изменения, перед
обновлением можно вернуться к форме. При ручной перезагрузке или закрытии
вкладки несохранённый ввод теряется: постоянного хранения черновиков нет.

## Production

Например, фронтенд размещается на `https://frontend.example.org`, API — на
`https://api.example.net`. Перед сборкой задайте адрес API в окружении CI
или в игнорируемом файле `.env.production.local`:

```dotenv
VITE_API_URL=https://api.example.net/api/v1
```

```bash
bun install --frozen-lockfile
bun run build
```

Загрузите содержимое `dist/` на статический HTTPS-хостинг. Node, Bun и Vite
на сервере раздачи статики не нужны; dev/preview не используются как
production-серверы. API доступен браузеру по собственному URL.

Vite подставляет `VITE_*` **во время сборки**. При смене URL API пересоберите
и заново разместите `dist/`. Эти значения доступны браузеру; секреты в них
не передаются. См. [переменные окружения Vite](https://vite.dev/guide/env-and-mode).

На бэкенде задайте production-настройки, свою БД и:

```dotenv
APP_ENV=production
ALLOW_INSECURE_COOKIES=false
ALLOWED_ORIGINS=["https://frontend.example.org"]
COOKIE_SAMESITE=none
COOKIE_PARTITIONED=true
CSRF_SECRET=<случайный секрет из настроек бэкенда>
```

Бэкенд поддерживает cookie `SameSite=None; Secure; Partitioned` для разных сайтов.
Поддержка CHIPS зависит от браузера; полный запрет cookie и старые браузеры могут
мешать авторизации. Для CORS с cookie нужен точный разрешённый origin, не `*`.
Перед записью ofetch получает `/auth/csrf` с cookie и отправляет подписанный токен
в `X-CSRF-Token`. Токен хранится только в памяти и сбрасывается при смене сессии.
После CSRF-ошибки следующий явный запрос получает новый токен; запись автоматически
не повторяется. `CSRF_SECRET` задаётся только на бэкенде и не входит в `VITE_*`.
Регистрация и вход также требуют CSRF. Конфигурация и генерация секрета описаны
в README бэкенда.
Подробнее — [CORS с credentials](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS#requests_with_credentials).

Пример статического Nginx-хостинга внутри настроенного HTTPS `server`, без API-прокси:

```nginx
root /var/www/task-tracker/dist;
index index.html;

location = /sw.js {
    add_header Cache-Control "no-cache";
    try_files $uri =404;
}

location = /index.html {
    add_header Cache-Control "no-cache";
}

location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
    try_files $uri =404;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

Fallback в `index.html` нужен для обновления и прямого открытия внутренних
адресов, включая `/invite/:token`.
Для Vercel он настроен в `vercel.json`: это также позволяет открывать `/tasks`,
указанный в манифесте как стартовый адрес установленной PWA. Файл должен входить
в корень проекта Vercel; после его добавления нужен новый деплой фронтенда.
Деплой должен сохранять старые файлы с хэшами в `/assets/` для уже открытых
вкладок до принятия обновления. Приложение автоматически не публиковалось.

Проверка конфигурации API: типы, ESLint и 12 тестов фронтенда прошли.
Сборка проверена с нестандартным origin, префиксом пути и завершающим `/`;
URL корректно встроен в настройки ofetch. Пустой, относительный и FTP-адрес
отклоняются до сборки. Проверена HTTP-раздача готового `dist/` без env
у preview: внутренние ссылки, manifest и service worker доступны.
Прежние предупреждения Zod и размера общего JS-чанка сохраняются.
Авторизация на реальных production HTTPS-доменах в эту проверку не входила.

## Контракты и ограничения

Источники: README, `app/schemas`, `app/api/routers` бэкенда и его OpenAPI.
Логин: 3–32 символа; пароль: 6–128. Дополнительных правил состава символов
и собственных ограничений длины названия/описания нет.

Текущий `TaskRead` содержит только ID автора и исполнителя. Логины
разрешаются через текущую сессию и списки участников. После ухода человека
из группы API больше не возвращает его логин: интерфейс показывает
«Бывший участник». Для исторического логина потребуется отдельное изменение
контракта бэкенда, например безопасные сведения об авторе/исполнителе в TaskRead.
Бэкенд здесь не изменён.

Нет повторений, сроков, комментариев, вложений, уведомлений, передачи
владения, постоянных черновиков, фоновой синхронизации или очереди изменений.
Мобильную установку в нативном Safari/Chrome на реальном устройстве нужно
проверить отдельно.

## Изолированная проверка

Не запускайте сценарии создания/удаления на пользовательской БД.
Для проверки использовался отдельный временный контейнер PostgreSQL 18
на `127.0.0.1:55433`, без томов. Существующие Alembic-миграции применены
к тестовой БД. Интеграционные pytest-тесты запускались только с
`AUTH_TEST_DATABASE_URL`, указывающим на неё; обычный `DATABASE_URL`
для интеграционных тестов не подставлялся.

```bash
cd /home/sergey/proj/task-tracker
AUTH_TEST_DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:55433/TEST_DB \
  .venv/bin/python -m pytest tests/test_auth_integration.py tests/test_tracker_integration.py -q
```

У существующих исполняемых файлов `.venv/bin/alembic` и других скриптов
может быть старый абсолютный путь в shebang. Если появляется `bad interpreter`,
используйте `.venv/bin/python -m alembic` / `-m uvicorn` / `-m pytest`.
Для ручной проверки сервер также должен работать с отдельной тестовой БД.
